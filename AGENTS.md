# Working on this repo as an agent

Rxova React Inputs: a suite of headless, accessible React input components — currency, rating,
one-time-code, password, phone, date, time, measurement, tags and file — published as independent
npm packages plus a meta-package.

[`CONTRIBUTING.md`](CONTRIBUTING.md) is the reference and stays the source of truth: the
[architecture table](CONTRIBUTING.md#architecture), [setup](CONTRIBUTING.md#setup),
[which suite a test belongs in](CONTRIBUTING.md#which-suite-does-a-test-belong-in),
[the release process](CONTRIBUTING.md#release). Read it. This file only covers what an agent gets
wrong, which is a different and much shorter list.

## Four things to know before editing

| Path                                           | What it actually is                                                                                     |
| ---------------------------------------------- | ------------------------------------------------------------------------------------------------------- |
| `packages/*/src/types.ts`                      | The public prop surface. Semver-covered. Its TSDoc **is** the published API reference.                  |
| `apps/docs/src/content/docs/components/*/api/` | **Generated by TypeDoc at build time and gitignored.** Never edit. Edit the TSDoc in `types.ts`.        |
| `apps/docs/src/content/docs/**` (the rest)     | Hand-written prose. Yours to edit.                                                                      |
| `packages/utils/`                              | Private tooling — the release gate and the check scripts. Never published, never imported by a package. |

## The gate

```bash
pnpm verify     # what pre-push runs, in CI's order — run this before you claim done
```

Scope while iterating: `pnpm --filter @rxova/react-otp-input test:browser`.

`pnpm verify` is not a formality. It runs the audit, format, doc-snippet, browser-config, lint,
typecheck, coverage, build, size, export and pack checks in the order CI does, so a failure here is
the failure you would otherwise discover on the PR.

## Invariants, and what enforces them

Each of these has caught a real regression. The right-hand column is why you cannot "just try it and
see" — several are enforced late, so breaking one is cheap to do and expensive to discover.

| Invariant                                                                                                                                                                                                                                            | Enforced by                                     |
| ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------- |
| **Zero runtime dependencies.** `react` is the only peer (plus `react-dom` where needed).                                                                                                                                                             | review + `pnpm size` budgets                    |
| **No stylesheet to import.** Visual knobs are CSS custom properties and `data-*` hooks; only layout-critical CSS is inlined.                                                                                                                         | review                                          |
| **95% coverage per file** — a thinly-tested new file fails even when the repo average is fine.                                                                                                                                                       | `pnpm test:coverage`                            |
| **`types.ts` and the documented `data-*` attributes are semver API.**                                                                                                                                                                                | review                                          |
| **Styling hooks are namespaced `--rx-<slug>-*` / `data-rx-<slug>-*`**, using the package's own `rxova.slug`. Shared state hooks (`data-invalid`, `data-disabled`, `data-focused`, …) stay unprefixed on purpose, so one selector styles every input. | `pnpm check:tokens`                             |
| **A changeset for anything user-facing.**                                                                                                                                                                                                            | `check-changeset.ts` in CI                      |
| **Accessibility comes from platform semantics**, not from JavaScript reimplementing them. Reaching for a keydown handler to do what a real `<input>` or `radiogroup` already does means the markup is wrong.                                         | axe specs in `packages/*/e2e/`                  |
| **Conventional Commits**, types: `build chore ci docs feat fix perf refactor rename revert style test`. Scopes are free.                                                                                                                             | commitlint, on both the commit and the PR title |

### jsdom is never the layer for geometry, focus, caret or paste

jsdom has no layout engine and a fictional selection model. A jsdom assertion about a rect, a caret
position or a hover only re-reads the style string the test just wrote — it passes whether or not the
component works. These belong in `*.browser.test.tsx` (Chromium) or the package's `e2e/`. This is the
single most common way to add a test that proves nothing.

## Change these together

A behaviour change touches three surfaces, and shipping fewer than all of them ships an invisible fix:

1. `packages/<pkg>/src/types.ts` — the TSDoc, which becomes the published API reference
2. `packages/<pkg>/README.md` — what npm and `node_modules` show
3. `apps/docs/src/content/docs/components/<slug>/` — the prose

Grep for the prop name across all three before you call a change complete.

## Conventions worth matching

- **Comments explain why, not what.** This codebase's comments are unusually load-bearing — they
  record the bug that motivated a line. Match that: a comment restating the code is noise, and a
  removed "why" comment is a regression waiting to be reintroduced.
- **Discovery is derived, never declared.** `packages/utils/component-packages.mjs` finds components
  by their `rxova` manifest block. The docs sidebar, the redirects and the TypeDoc instances all read
  from it, so a new component needs no edit in any of them. Do not add a hardcoded list.
- **Check scripts export pure functions and guard the CLI entrypoint**, so tests drive them against
  temp-directory fixtures. See `apps/docs/scripts/check-readme-links.mjs` for the shape to copy.
